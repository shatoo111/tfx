# Протокол проверки

## TFX 0.4.0, 20 ноября 2026

На Windows 11 с реальным Telegram Desktop 7.4.4 локальный тест прошёл для всех шести тем. Он проверяет появление кадров, цветных и прозрачных пикселей в собственном буфере слоя, размеры и выключение. Дополнительно проверены перемещение и изменение размера окна, максимизация, сворачивание и возврат. Границы сравнивались с DWM, порядок окон — через Win32. Положение пользовательского окна восстанавливается после теста. В дополнительной проверке на той же машине открыты два экземпляра официального Telegram с отдельными пустыми профилями. При смене активного окна A → B → A один и тот же HWND слоя оказывался непосредственно над соответствующим HWND Telegram.

На macOS 15 GitHub Actions запускает официальный Telegram Desktop с начальным экраном без входа в аккаунт. Оба порядка запуска проверяются отдельными процессами теста. Вердикт для конкретного тега хранится в журнале его GitHub Actions. Переписка, заголовки окон и экран Telegram не считываются.

### Короткий замер нагрузки в Windows

Снег обычной плотности поверх открытого Telegram Desktop. Qt 6.8.3, GeForce RTX 5060, 12 логических процессоров. Снимались два интервала по 15 с после появления кадров. CPU — процесс теста с производственным слоем относительно всего процессора, GPU — время 3D-движка этого процесса по счётчикам Windows. Окно настроек и анимация предпросмотра в замер не входят.

| Режим | CPU | GPU 3D |
| --- | ---: | ---: |
| Обычный, 60 кадров/с | 0,68% | 1,59% |
| Экономичный, 30 кадров/с | 0,40% | 0,90% |

У стенда нет батареи. Энергопотребление на ноутбуках, перенос между физическими дисплеями с разным масштабом, сон, Spaces, полный экран и несколько окон на Mac остаются задачами аппаратной приёмки. [Обязательная проверка релиза](manual-test-plan.md).

## Итог

**Полный MVP ещё не принят:** приложение целиком не собрано и не проверено поверх Telegram на Windows или macOS. При этом C++-ядро, настройки, QML-интерфейс и реальный Metal-рендерер собраны и проверены отдельно. Это разные уровни проверки; успешный вывод снега в тестовом окне не подтверждает привязку к чужому окну.

Среда: macOS 26.6, arm64, GPU Apple A18 Pro, Qt 6.8.3, переносимый Zig 0.14.1 / Clang 19.1.7, CMake 3.31.8, Ninja 1.12.1. На исходном компьютере не было Qt/CMake/Xcode CLT. Для проверок официальные переносимые Qt, CMake, Ninja и Zig скачаны в `/tmp`; системные инструменты и разрешения безопасности не изменялись.

## Обнаруженные и исправленные проблемы

- Синтаксическая ошибка QML после группы `anchors`.
- Явные размеры элементов, управляемых layout; заменены на implicit sizes.
- Неявные QML context properties заменены required properties и явной передачей объектов; включён bound component behavior.
- В установленном официальном Telegram Desktop проверен bundle ID `com.tdesktop.Telegram` и добавлен в обнаружение.
- При насыщении поля снег становился плоской полосой. Добавлен ограниченный неровный локальный максимум и регрессионная проверка силуэта; коэффициенты кешируются при resize.
- Software Scene Graph теперь явно отключает overlay с диагностикой вместо пустого визуального эффекта.

## Что не проверено

1. **Нативный macOS adapter не собран.** Полная CMake-конфигурация остановилась на отсутствии `OPENGL_INCLUDE_DIR` / `WrapOpenGL`: Qt Gui требует заголовки Apple SDK, которого нет. Это не проверка Objective-C++ кода. Для завершения нужны Xcode Command Line Tools и стандартная desktop-сборка из README.
2. **Windows adapter не собран и не запускался.** Нет Windows, MSVC/Windows SDK и Qt Windows toolchain. Подготовлены manifest, PowerShell-скрипт и CI workflow.
3. Click-through, фокус, фактическое обнаружение/сопровождение Telegram, full screen, Spaces/виртуальные рабочие столы, mixed-DPI, сворачивание, блокировка сессии, автозапуск и clean-machine deployment требуют [ручного протокола](manual-test-plan.md).
4. Нет замеров CPU/GPU и гарантии 30/60 FPS на пользовательском оборудовании. Сообщение Qt о vsync 16.67 ms не является бенчмарком приложения.
5. Не создавались и не публиковались готовые `.app` / `.exe` приложения. Подпись, notarization и CI на GitHub не запускались. ASan в этой среде не проверялся; UBSan проверялся.
